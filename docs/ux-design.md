# Beecord Studio 交互设计（macOS）

> 状态：**已定稿**（2026-10-14 评审通过，结论见 §6）。配套可点击原型：[`prototype/index.html`](prototype/index.html)
> （浏览器直接打开）。评估通过后按本文档落 SwiftUI 实现。
> 本文档聚焦信息架构、关键流程与状态处理。
> 2026-10-16：原型 v0.2 补充空态、未选择态与蓝牙不可用面罩；新增状态已评审确认。

## 1. 设计原则

1. **本地优先**：录音与转写产物默认只存本机；云端 AI 显式配置、显式开启、首次开启有出域提示。
2. **macOS HIG 合规**：`NavigationSplitView`（侧栏+详情）；设置走标准 Settings 窗口（⌘,）；
   工具栏动作最少化；支持键盘快捷键与系统深色模式。
3. **开发者友好但不对普通用户露骨**：协议控制台默认隐藏，设置里开"开发者模式"才出现在侧栏。
4. **协议与 UI 解耦**：BuzzLink 客户端逻辑独立为 SDK 层，任何实现 BuzzLink 协议的设备都可接入，
   UI 不区分设备来源。

## 2. 信息架构

侧栏 3(+1) 项 + 标准设置窗口：

| 入口 | 内容 | 备注 |
|---|---|---|
| **设备** | 连接管理 + 设备信息 + 设备端文件同步 | 首页/默认页 |
| **录音库** | 已下载录音的管理/播放/转写/AI 纪要 | 左列表右详情 |
| **协议控制台** | 帧级日志 + 原始命令发送 + 会话导出 | 开发者模式开启后出现 |
| 设置（⌘,） | 通用 / AI 服务 / 转写 / 关于 | 标准 Settings 窗口；入口=侧栏脚标行右侧齿轮（原型内简化为侧栏页） |

## 3. 关键流程

### 3.1 连接设备

> **P0 注（2026-10-16 评审确认）**：连接即扫描一体（`connect()` 一步式），P0 无"发现设备"
> 卡片列表 / RSSI——该卡片为 **P1（多设备）功能**，原型已标注（v0.2）。多设备发现需
> `BLETransport` 增加发现结果流 + `connect(to:)`，跨机实测后扩展
> （见 studio-tech-design §9 开放问题）。

1. 应用启动即连接（后台持续）；设备页显示"正在连接设备…"动效（附配对引导副行）；
2. 连接成功 → 已连接：设备信息卡（型号/固件/电量/存储用量条）+ 文件区；
   侧栏底部脚标变绿（设备名 已连接）；
3. 长时间未发现 / 断开后 → 空态：「未发现 Beecord 设备」+
   「确认手表已开机并位于 Mac 附近，然后三击电源键进入配对模式。」+【重新扫描】。

### 3.2 文件同步（设备页）

- 文件表：勾选 / 文件名（起录时间）/ 时长 / 大小 / 状态（未下载 · 下载中 xx% · ✓ 已校验）；
- 工具行：全选、【下载所选(n)】、自动同步开关（连接后自动拉新录音，**默认开启**；关闭时可手动勾选补充）、刷新；
- 下载中：底部整体进度（x/y 个、当前文件进度、速率 KB/s、预计剩余），可取消；
- 完成：toast 提示；每行状态变 ✓（CRC 校验 + 页修复均内置，用户无感）。

### 3.3 录音库（左列表右详情）

> **v0.3 同步（2026-10-16，原型已评审基线）**：徽标改双行（转码态 + 转写态）；转写/纪要
> Tab 为 P1 占位（转写 T9、纪要 T10，占位按钮 disabled）；导出三格式；标签推 P1。

- 列表：按录制时间**新→旧**排序；列表头标注排序规则与条数；
- 列表项：标题（可重命名，默认=起录时间）、日期·时长、**双行徽标**——
  上行转码态（待转码 / 转码中 x% / 转码失败 / 已就绪），下行转写态
  （未转写 / 转写中 / 已转写 / 已纪要，P1 占位演示）；空列表整页空态（见 §4）；
- 详情：标题（可重命名）；**转码未完成时播放器区为占位**（转码中"稍后即可播放" /
  待转码排队 / 转码失败 + 【重试】，ogg 原件仍可导出）；转码完成后播放器可用
  （波形、播放/暂停、±15s、倍速 1×/1.5×/2×、可点进度、时间）；
- 操作：重命名、导出 m4a / 导出 wav / **导出 ogg（原始）**、显示于 Finder、删除；
  删除弹 NSAlert 确认——标题「删除该录音？」、描述「未导出的原件将无法恢复」、
  主按钮"删除"红字、**默认焦点=取消**，确认后直接删除（无回收站，P1 评估）；
- 详情内 Tab：**转写**（占位引导："尚未转写（本地 whisper，内容不出本机）"，
  【开始转写】disabled，P1 T9）｜**AI 纪要**（占位引导："需在设置中配置 AI 端点与
  完成转写"，【生成纪要】disabled，P1 T10）；
- 边界：转码链 T6 交付（入库即转 + 存量补转）；搜索/过滤、标签、批量操作推 P1。

### 3.4 转写与 AI 纪要

- 转写：本地 whisper，按钮触发，进度可见；产物随文件保存；
- 纪要：转写就绪后【生成纪要】→ 流式输出；未配置 AI 端点 → 引导卡片跳设置；
- AI 服务预设：Kimi / DeepSeek / Qwen（通义千问）+ 自定义 OpenAI 兼容端点；不提供代理/自定义 header，保持配置面简洁；
- 导出：转写 txt/md，纪要 md；一键复制。

### 3.5 协议控制台（开发者模式）

- 预置命令（列文件/查信息/开始下载/结束校验）+ 自定义 hex 输入；
- 日志表：时间 / 方向(→←) / type / channel / payload 摘要；行点击展开 hex；
- 过滤（方向/type）+ 导出会话为 **JSON 测试向量**（可读性优先：时间戳/方向/type/hex 字符串等命名字段，可直接 diff；喂 `firmware/test_host`）。

## 4. 状态与异常

| 场景 | 表现 |
|---|---|
| 未发现设备 | 扫描结束后显示空态：配对引导 +【重新扫描】，不保留永久旋转的扫描动效 |
| 已连接但设备无录音 | 文件区显示"设备上还没有录音"+ 录音/刷新引导；隐藏空表头，全选与下载禁用，自动同步保留 |
| 录音库为空 | 整页空态说明同步后来源，主按钮【前往设备同步】；不显示无数据的列表与播放器 |
| 录音库未选择 | 保留左侧列表，右侧显示选择引导；可选最近录音，避免空白详情页 |
| 下载中断（断连） | 该文件标"未完成"，重连后可重新下载；整体进度暂停并提示 |
| CRC 校验失败 | 行内红色标记 + 【重试】；连续失败提示可能链路问题 |
| 设备低电量（<15%） | 信息卡电量变橙 + 建议先充电 |
| 设备存储将满（>90%） | 同步前警告条 |
| AI 端点未配置/测试失败 | 纪要 Tab 引导态；设置页状态灯红/绿 |
| 无权限（蓝牙未授权/关闭） | 全局面罩 +【打开系统设置】与【重试】 |

## 5. 原型说明与边界

- 原型为**单文件 HTML**（无依赖），模拟：扫描→连接→列表→下载→播放→转写→纪要→控制台→设置 全链路；
- 标题栏的**评审场景**仅为原型控件，可直接切换：主流程、未发现设备、设备无录音、录音库为空、
  录音库未选择、蓝牙不可用；该控件不进入产品 UI；
- 数据全部为演示用 mock（文件名/时长/帧日志等）；场景切换只重载 mock 状态，不操作真实设备或文件；
- 不限于评审视觉细节（图标/间距以 SwiftUI 实现时按 HIG 微调），重点评估**信息架构与流程**。

## 6. 评审结论（2026-10-14 已决）

1. **控制台保持侧栏一级入口**（开发者模式门控，后期可随时隐藏），不收进设备页。
2. **自动同步默认开启**；设备页保留手动勾选与【下载所选】作为补充。
3. **转写/纪要维持详情页内 Tab**，不拆独立侧栏项。
4. **AI 配置不扩展**（无代理/自定义 header）；预设 Kimi / DeepSeek / Qwen（通义千问）+ 自定义 OpenAI 兼容端点。
5. **控制台导出采用 JSON 测试向量**（可读性优先），不做二进制格式。
